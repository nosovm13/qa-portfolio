# Test Plan: API Testing — Postman

## Объект тестирования

JSONPlaceholder Posts API.

## Цель тестирования

Проверить основные операции REST API для ресурса posts: получение, создание, обновление, удаление и фильтрацию данных.

## Область тестирования

В рамках проекта проверяются:

- получение поста по ID;
- создание нового поста;
- обновление существующего поста;
- удаление поста;
- фильтрация постов по title;
- обработка запроса с несуществующим ID;
- проверка статус-кодов;
- проверка структуры JSON-ответа;
- проверка значений в ответе.

## Вне области тестирования

В рамках проекта не проверяются:

- авторизация и аутентификация;
- права доступа;
- безопасность API;
- нагрузочное тестирование;
- работа базы данных;
- реальные изменения данных на сервере;
- контрактное тестирование по OpenAPI-спецификации.

## Методы

- GET
- POST
- PUT
- DELETE

## Тестовая среда

- Инструмент: Postman
- API: JSONPlaceholder
- Формат данных: JSON

## Тестовые данные

- `post_id`: `1`
- `doesnt_exist_post_id`: `999999`
- `title`: `Test post`
- `updated title`: `Updated test post`
- `userId`: `1`

## Критерии начала тестирования

Тестирование может быть начато, если:

- API доступно;
- Postman установлен;
- импортированы коллекция и environment;
- заполнены переменные окружения;
- запросы отправляются без сетевых ошибок.

## Критерии завершения тестирования

Тестирование считается завершённым, если:

- выполнены все запросы из коллекции;
- проверены позитивные и негативные сценарии;
- все автопроверки Postman выполнены;
- подготовлен краткий отчёт о тестировании.

## Риски и ограничения

- JSONPlaceholder является demo API, поэтому данные не сохраняются как в реальном backend.
- Поведение demo API может отличаться от поведения production API.
- Проверки выполняются только на уровне HTTP-запросов и JSON-ответов.
