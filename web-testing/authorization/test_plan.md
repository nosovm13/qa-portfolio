# Test Plan: Authorization

## Объект тестирования

Форма авторизации Yandex ID в mobile web приложении.

## Цель тестирования

Проверить, что пользователь может пройти авторизацию с валидными данными, а приложение корректно обрабатывает невалидные данные, пустые поля, ошибки ввода и сценарии двухфакторной аутентификации.

## Область тестирования

В рамках тестирования проверяются:

- вход по email;
- вход по номеру телефона;
- ввод валидного пароля;
- ввод неверного пароля;
- ввод несуществующего логина;
- валидация пустых полей;
- валидация некорректного email;
- обработка пробелов в поле логина;
- переключение видимости пароля;
- сценарии двухфакторной аутентификации;
- отображение сообщений об ошибках;
- базовое отображение формы на mobile web.

## Вне области тестирования

В рамках данного проекта не проверяются:

- безопасность авторизации;
- защита от brute force;
- работа backend-логики;
- работа базы данных;
- восстановление доступа к аккаунту;
- регистрация нового пользователя;
- нагрузочное тестирование;
- кросс-браузерное тестирование на всех браузерах;
- тестирование на реальных пользовательских данных.

## Виды тестирования

- функциональное тестирование;
- позитивное тестирование;
- негативное тестирование;
- UI testing;
- smoke testing;
- regression testing.

## Тестовая среда

- Платформа: Mobile Web
- ОС: Android
- Браузер: Google Chrome

## Тестовые данные

В проекте используются только тестовые данные:

- email: `user@example.com`
- phone: `+79990000000`
- valid password: `ValidPassword123`
- invalid password: `InvalidPassword123`
- invalid 2FA code: `000000`
- valid 2FA code: `123456`

## Критерии начала тестирования

Тестирование может быть начато, если:

- форма авторизации доступна;
- поля логина и пароля отображаются;
- кнопка входа доступна для проверки;
- тестовая среда подготовлена;
- определены тестовые данные.

## Критерии завершения тестирования

Тестирование считается завершённым, если:

- подготовлены тест-кейсы;
- проверены основные позитивные и негативные сценарии;
- проверена валидация обязательных полей;
- проверены сообщения об ошибках;
- оформлен краткий отчёт о тестировании.

## Риски

- Поведение формы может отличаться в зависимости от устройства, браузера или версии приложения.
